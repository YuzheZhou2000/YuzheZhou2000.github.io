The work 我做的事

Three layers of the same problem. 同一个问题的三个层次。

01

Agent infrastructure Agent 基础设施

Designing the execution paths that carry context, tools, reasoning, usage, and terminal state from an idea in the editor to a result the user can trust. 设计承载 Context、Tools、Reasoning、Usage 与终态的执行链路，把编辑器里的一个想法， 变成用户可以信赖的结果。

02

Model systems 模型系统

Building a stable runtime over changing models and providers, with clear capability contracts, consistent streaming semantics, cache-aware context, and deliberate routing. 在持续变化的模型与 Provider 之上建立稳定运行时，用清晰的能力契约、一致的流式语义、 Cache 感知的 Context 与可解释的路由隔离变化。

03

Production reliability 生产可靠性

Treating queues, retries, fallback, isolation, and observability as product behavior, because reliability is part of how an intelligent tool feels. 把排队、重试、降级、隔离与可观测性当作产品行为来设计，因为可靠性本身就是智能工具体验的一部分。

Questions I return to 反复思考的问题

The details shape the intelligence. 细节最终塑造了智能。

01 / FAILURE

How should an agent fail? Agent 应该怎样失败？

Failure should be bounded, understandable, and recoverable without turning a small downstream problem into a system-wide event. 失败应该有边界、可理解、可恢复，而不是让一个下游小问题演变为全局事件。

02 / CONTEXT

What makes context reusable? 什么让 Context 可以复用？

Good caching begins long before the cache: stable prompts, deterministic tools, append-only histories, and routing that respects locality. 好的缓存远在 Cache 之前就开始了，包括稳定的 Prompt、确定性的 Tool、追加式历史与尊重局部性的路由。

03 / BOUNDARIES

Where should differences end? 差异应该在哪里停止？

Providers can differ deeply without making every product layer understand their protocols, parameters, errors, and streaming lifecycles. Provider 可以差异巨大，但不应该让每一层产品代码都理解它们的协议、参数、错误与流式生命周期。
